Normal developer build commands (not an automatic execution authorization):

~~~sh

dotnet build tests/Integrity.Tests/Integrity.Tests.csproj -c Release --no-restore
dotnet run --project tests/Integrity.Tests -c Release --no-build
~~~

Optional focused interruption proof (owned test children only):

These intentionally degraded examples return2. The second recovery command
verifies completed output; it is not an interruption test. Generated source,
decisions and summaries are canonical UTF8/LF. Use fresh destinations.

The separate small `demo <new-directory>` command checks expected example
outcomes and all3 A2/A3 canonical files, returning0 when those checks match.
It adds no new framing, sequence or recovery semantics.

## Technology-refresh execution boundary

The refresh preserves CSV, synthetic, sequence and recovery semantics,
independent literal oracles and the separate0.6.0 CSV action pins. No A4 rerun.
.NET11 x64 requires x86-64-v2 and native OS prerequisites. See the actual
[delivery summary](evidence/technology-refresh-20261117.json).

For Windows self-contained restore/publish, use
`-p:DisableTransitiveFrameworkReferenceDownloads=true` on both commands.
The documented SDK property omits frameworks this plain console app does not
reference; its actual RID graph requires CoreRuntime11.0.0 only. Missing required
packs still fail. Use `--locked-mode`, `-p:SelfContained=true`,
`-p:RuntimeFrameworkVersion=11.0.0`, `-r win-x64` and a separate
`-p:NuGetLockFilePath=<actual-Windows-RID-lock>` on restore; use matching properties
with `--no-restore --self-contained true` on publish. Keep original runtime notices.

The signed `cli-v0.6.2-preview.1` runtime tag intentionally avoids the existing
Actions tag filters. Direct publication reuses the tested archives, verifies
both source/runtime manifests and signs their actual checksums. Main/feature
delivery heads use `[skip ci]`; no release/create workflow exists. Do not trigger
Actions or weaken any required check, trust, security or billing setting.
